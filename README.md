# No. Series Manager

A Business Central extension that creates date-based **No. Series Lines** ahead of time from a pattern, so posting never stops because a period has no number series line.

## What it does

Instead of creating one No. Series Line per period by hand, you define a **pattern** (for example `CCYY-10000`) and a **cadence** (day, week, month, quarter, year). The extension generates one line for each period in the year following a start date, with the starting, ending and warning numbers calculated for you.

Example: pattern `INV-YYMM-0001`, cadence *Month*, start date 2027-01-01 creates 12 lines:

| Starting date | Starting No. | Ending No. |
|---|---|---|
| 2027-01-01 | INV-2701-0001 | INV-2701-9999 |
| 2027-02-01 | INV-2702-0001 | INV-2702-9999 |
| … | … | … |

## Usage

1. Open **No. Series** and select a series.
2. Choose **Processing > Create No. Series Lines** (also available from **No. Series Lines**).
3. Fill in the dialog:

| Field | Description |
|---|---|
| Pattern | Prefix tokens followed by the starting number, e.g. `CCYY-10000`. |
| Cadence | How often a new line is created: Day, Week, Month, Quarter, Year. |
| Start Date | Date the first line starts on. Lines are created for one year from this date. Defaults to 1 January of the first year with no existing lines. |
| Increment-by No. | Increment applied to each created line (default 1). |
| Warning No. Offset | How many numbers before the ending number a warning is given. 0 = no warning number. |

4. Choose **OK**. The pattern is saved for the series (so the dialog is prefilled next time) and the lines are created. A message reports how many lines were created.

### Pattern tokens

| Token | Replaced with |
|---|---|
| `CC` | Century (2 digits) |
| `YY` | Year (2 digits) |
| `MM` | Month (2 digits) |
| `DD` | Day (2 digits) |
| `WW` | Week number (2 digits) |
| `Q` | Quarter (1–4) |

Any other character is kept as is. The pattern **must end with the starting number** (digits). The number of trailing digits sets the width of the number part, and the ending number is all nines (e.g. `10000` gives an ending number of `99999`).

### Rules and validation

- A start date is required.
- The numeric part may be at most 18 digits.
- The resulting number may not be longer than the `Pattern` field (20 characters).
- Every period must produce a unique prefix. Pattern `INV-10000` with a monthly cadence is rejected; add tokens such as `YY` or `MM`.
- If the warning offset is larger than the range of the starting number, creation is rejected.
- Existing lines are never changed or duplicated: a period is skipped if a line already exists with the same starting date, or the same starting number.

### Flow

```
No. Series (action) -> Codeunit.RunDialog
                         loads/initializes pattern, default start date
                       -> Page "Create No. Series Lines" (modal)
                          OK -> Codeunit.SaveAndCreateLines
                                 validate -> split pattern -> compute periods
                                 -> build unique prefixes -> save pattern
                                 -> InsertLines (skip existing)
```

## Permissions

Assign **NSMGR NSHLG, EDIT** to users who create lines, and **NSMGR NSHLG, VIEW** to users who only need to see patterns.
